# W1.1: specify the portable release and provider boundary

> **Status: ready**
> **Implementation code is explicitly out of scope**

## Outcome

A reviewed manifest v1 and provider contract make it possible to build PND,
artist-site, and embed experiences without duplicating protocol behavior or
making independent interfaces depend on PND runtime services.

## Scope

### Owned

- Define manifest v1 fields and truth class for every field.
- Separate artist-authored, protocol-derived, indexed, and PND-editorial data.
- Define serialization, versioning, capability negotiation, and signature
  payloads.
- Define provider interfaces for current protocol state, indexed history,
  identity, media, and editorial context.
- Define which capabilities must work with PND endpoints blocked.
- Define package boundaries for `@pin/release-spec`, `@pin/surface-kit`, and
  `@pin/surface-react`, including dependency direction.
- Define parity, degraded-state, and compatibility test matrices.
- Map current duplicated source to its future owner.

### Excluded

- Moving source files or creating the packages.
- Designing the final PND homepage or collection layout.
- Implementing Studio checkups, exports, deployment, feeds, or embeds.
- Choosing a CMS or paid service.

## Required design properties

### Manifest

- Network and contract references are explicit.
- Artist declarations are signable and portable.
- PND editorial fields cannot masquerade as artist declarations.
- Indexed observations include source and coverage semantics rather than being
  serialized as timeless fact.
- Unknown capabilities degrade safely across manifest versions.
- Secrets, PND authentication, and private subscriber data are forbidden.

### Providers

- Core provider: price, supply, lifecycle inputs, renderer data, and
  transaction preparation.
- History provider: optional indexed mints, sales, bids, and ownership.
- Identity provider: optional ENS or profile context.
- Media provider: canonical URI plus optional prepared delivery asset.
- Editorial provider: optional PND-authored feature and launch context.

The core provider cannot import a PND database or HTTP route. Optional provider
failure produces typed unavailable or partial states.

### Package direction

```text
@pin/abi + @pin/addresses
              ↓
      @pin/release-spec
              ↓
       @pin/surface-kit
              ↓
      @pin/surface-react
              ↓
apps/web | artist template | future embeds
```

No lower package imports an upper package or application.

## Acceptance scenarios

- A canonical Surface fixed-price release can be represented.
- A custom-minter release such as Homage can declare unsupported generic
  capabilities without lying.
- An artist site can render and transact with PND endpoints blocked.
- PND can add indexed history and editorial context without changing the core
  manifest.
- An artist-provided site URL is attributable but not described as verified.
- A future authored exhibition can reference releases without changing release
  ownership or availability.
- Version mismatch produces explicit capability reduction.
- Current copied render and transaction code has one proposed destination.
