## Data and dependency contract

- Inputs and truth classes: Postgres browse/history observations; shared
  provider protocol state on action surfaces; artist manifest declarations;
  repository-backed PND editorial declarations.
- Read owner: Postgres owns browse, profile, media, ownership, and history;
  the shared provider owns bounded current release action state.
- Write owner: the shared provider prepares release transactions; existing
  wallet assemblies submit them.
- Freshness and finality: preserve W0.1 indexed freshness labels and W1.3's
  12-second state, 30-second validation, and immediate pre-write quote bounds.
- External services: existing RPC and media gateways only; optional services
  degrade independently.
- Request-time RPC effect: no browse/profile scans or card-level live RPC;
  bounded live reads only on the focused release action.
- Worker or indexer effect: none unless a separately approved truth gap is
  discovered and assigned back to W0.
- Database and migration effect: none.
- Storage and recurring-cost estimate: repository editorial data only; $0.

## Design

Build from the accepted information hierarchy, not route-by-route feature
mirroring. Shared view models must expose truth class, freshness, media state,
availability, and action capability before assemblies choose layout.

The homepage is the edited front door; Releases pairs authored selection with
the complete record; release pages are authoritative action and artwork
surfaces; profiles organize overlapping artist and collector histories around
work state; Activity is the durable event journal; About explains the promise
and boundaries in audience language. `Indexed` remains help text, never a
primary product label.

## Acceptance scenarios

- A real featured release remains visible independent of record pagination.
- Current, upcoming, available, sold/transferred, collected, and unknown states
  remain distinct without inventing availability.
- One artist-collector address presents both roles without a persona switch.
- Empty, stale, partial, database-unavailable, loading, failed-media, and
  optional-provider-outage states retain useful navigation and honest copy.
- Desktop and 390px review covers every owned route on the exact Netlify
  preview with live read-only data, no dummy content, broken media, or
  page-level overflow.
- Representative route performance is measured; no full-grid RPC fan-out or
  request-time historical log scan is introduced.
- Existing shared parity and PND-offline tests remain green.
